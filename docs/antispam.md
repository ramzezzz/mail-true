# Антиспам Mail.True: что подключено и как это проверять

Фильтрацией занимается **Rspamd** (milter для Postfix, порт 11332). Требования
и обоснование — в `docs/antispam-spec.md`. Здесь — что реально сделано,
где лежат настройки и как проверить, что фильтр работает.

Повторяемая проверка: `bash infra/test-antispam.sh` (38 проверок).

---

## 1. Свой рекурсивный резольвер — почему без него ничего не работает

Бесплатные списки Spamhaus, URIBL и SURBL отвечают только тем резольверам,
которые рекурсивно резолвят сами. Запрос, пришедший через публичный резольвер
(8.8.8.8, 1.1.1.1, DNS хостера, встроенный DNS Docker), они не обслуживают —
вместо ответа возвращают «заглушку». Формально ответ есть, фактически проверка
не работает и молчит. Это худший вариант: фильтр выглядит настроенным, а
ничего не ловит.

Так это выглядит на нашем стенде (вывод `infra/test-antispam.sh`, п. 1.1):

```
       . через unbound:            127.0.0.10 127.0.0.2 127.0.0.4
       . через публичный резольвер: 127.255.255.254
```

`127.0.0.2/4/10` — контрольная запись Spamhaus (адрес числится в SBL, XBL и
PBL одновременно). `127.255.255.254` — «запрос отклонён, вы ходите через
публичный резольвер».

Поэтому в стек добавлен сервис **unbound** (`infra/unbound/`):

| Что                | Значение                                                              |
| ------------------ | --------------------------------------------------------------------- |
| Образ              | `alpine:3.20` + пакет `unbound` (сборка `infra/unbound/Dockerfile`)   |
| Адрес в сети стека | `${RESOLVER_IP}` = `172.28.0.53` (фиксированный)                      |
| Память             | **7–8 МБ** RSS при кэшах из `infra/unbound/unbound.conf`              |
| Наружу             | порт не публикуется; `access-control` отвечает только приватным сетям |
| DNSSEC             | включён, корневой якорь обновляет `unbound-anchor` при старте         |

Кто через него ходит:

- **rspamd** — дважды: `dns { nameserver }` в `override.d/options.inc`
  (пишет entrypoint из `RESOLVER_IP`) и `dns:` у сервиса в docker-compose;
- **postfix** — через `dns:` у сервиса (MX/A-записи, проверки при приёме).

Имена контейнеров (`redis`, `dovecot`, …) резолвятся по-прежнему: у postfix их
отдаёт встроенный DNS Docker, а собственному резольверу rspamd их отдаёт
unbound через `stub-zone` на `127.0.0.11`. То есть **доставка почты не зависит
от unbound** — если он умрёт, LMTP и SASL продолжат работать.

Настройки резольвера, важные для почты:

- `cache-min-ttl: 60` — не долбить списки одинаковыми запросами (экономия
  бесплатного лимита);
- `serve-expired: yes` — если внешний источник недоступен, отдаём протухший
  ответ из кэша: почта важнее свежести DNSBL;
- `qname-minimisation`, `harden-*` — гигиена, чтобы резольвер не стал
  инструментом для чужих атак.

Диагностика внутри контейнера:

```bash
docker compose -f infra/docker-compose.yml exec unbound \
  sh -c 'dig @127.0.0.1 2.0.0.127.zen.spamhaus.org A +short'
docker compose -f infra/docker-compose.yml exec unbound \
  sh -c 'unbound-control -c /etc/unbound/unbound.conf stats_noreset | head -20'
```

Чтобы посмотреть каждый уходящий запрос: `UNBOUND_LOG_QUERIES=yes` в
`infra/.env` и `docker compose up -d unbound`. На боевом сервере держать `no` —
лог растёт очень быстро.

Правила лежат в штатном `modules.d/rbl.conf` образа; наши изменения —

### 2.3 Коллективная нечёткая база Rspamd

`infra/rspamd/local.d/fuzzy_check.conf` — публичное хранилище
`fuzzy.rspamd.com` (серверы находятся по SRV-записи `_fuzzy._tcp.rspamd.com`,
то есть без работающего резольвера правило молча не поднялось бы).
Режим **только чтение**: письмо сравнивается с тем, что другие серверы уже
пометили как спам, свои сигнатуры мы туда не отправляем. Символы
`FUZZY_DENIED` (вес снижен до 5.5), `FUZZY_PROB`, `FUZZY_WHITE`.

### 2.4 Собственные механизмы Rspamd (были и остались)

Байесовский классификатор с автообучением (Redis), SPF/DKIM/DMARC, ARC,
эвристики заголовков и MIME, фишинг, ограничение частоты, подпись исходящих
DKIM. Плюс модуль `replies` (`local.d/replies.conf`) — автоматический белый
список: ответ на письмо, отправленное нашим пользователем, получает символ
`REPLY` с весом −4. Это и есть «белый список тех, с кем переписывается
пользователь», он ведётся сам.

### 2.5 Антивирус — выключен по умолчанию

`infra/rspamd/local.d/antivirus.conf` + профиль `clamav` в docker-compose.

**Замеренный расход: 1.03 ГиБ** памяти контейнером сервиса `clamav` с полными
базами (проверено на этом стенде). Весь остальной стек — 291 МиБ. На VPS с
2 ГБ антивирус съедает больше половины машины, поэтому включается двумя
осознанными действиями:

```bash
# 1) infra/.env
CLAMAV_ENABLED=true
# 2) поднять контейнер и перечитать конфиг rspamd
docker compose -f infra/docker-compose.yml --profile clamav up -d
```

Проверено: при `CLAMAV_ENABLED=false` rspamd пишет в лог
`lua module antivirus is disabled in the configuration` и к clamd не ходит;
при `true` тестовый образец EICAR даёт
`CLAM_VIRUS (0.00)[Eicar-Signature]` и действие `reject`.

Найденный вирус — не «баллы», а сразу отказ. Если clamd не отвечает, письмо
пропускается дальше (fail-open): падение антивируса не должно останавливать
почту.

## 3. Ограничения бесплатного использования — честно

| Источник                                      | Условия                                                                                                                                                                                                                                                                          | Что это значит для нас                                                                                 |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Spamhaus** (ZEN, DBL)                       | Бесплатно только для некоммерческого использования и небольших объёмов: ориентир — до 300 тыс. запросов и до 100 тыс. писем в сутки, **обязательно со своего рекурсивного резольвера**. При превышении зона начинает отвечать `127.255.255.254`/`127.255.255.255` вместо данных. | Для личного и небольшого корпоративного сервера — годится. При росте нужен платный Data Query Service. |

| **DNSWL**                                     | Бесплатно до 100 тыс. запросов в сутки с одного IP.                                                                                                                                                                                                                              | Белый список, при блокировке — `DNSWL_BLOCKED` (вес 0).                                                |
| **MSBL EBL, blocklist.de, SEM, virusfree.cz** | Бесплатны, без регистрации, разумные объёмы.                                                                                                                                                                                                                                     | Работают.                                                                                              |
| **Коллективная нечёткая база rspamd.com**     | Бесплатно, без регистрации, только чтение.                                                                                                                                                                                                                                       | Работает.                                                                                              |
| **SenderScore (Validity)**                    | **Требует регистрации.** Незарегистрированным IP всегда отвечает `127.255.255.255` независимо от объёма.                                                                                                                                                                         | **Выключен явно** (`local.d/rbl.conf`), чтобы не создавать видимость работающей проверки.              |

`SPAMHAUS_BLOCKED_OPENRESOLVER`, `URIBL_BLOCKED`, `SURBL_BLOCKED`,
`DBL_BLOCKED*`, `DNSWL_BLOCKED`) имеют **вес 0** — это не признак спама, а
сигнал администратору. Их надо показывать в админке в разделе «Состояние
источников»: если они начали появляться, проверки перестали работать.

## 4. Пороги и веса

### Два порога

`infra/rspamd/local.d/actions.conf`:

```
reject = 15;          # отказ на этапе SMTP: отправитель получит ошибку
add_header = 6;       # пометка X-Spam: Yes -> папка Спам
rewrite_subject = null;
greylist = null;      # выключен: в dev мешает мгновенной доставке
```

Отправитель, чьё письмо отклонено, получает отказ и об этом узнает — письмо
не теряется молча. Между «похоже на спам» и «точно спам» намеренно большой
разрыв: чтобы дойти до отказа, нужно несколько независимых сработок.

### Одна сработка не отправляет в спам

Штатные веса rspamd для внешних списков — 6.5–7.5, то есть **одного** попадания
хватало, чтобы письмо ушло в спам. Списки ошибаются, особенно с адресами
больших почтовых служб и с серверами, недавно сменившими владельца. Поэтому
вес каждого списка опущен ниже порога 6 (`local.d/surbl_group.conf`,
`local.d/rbl_group.conf`, `local.d/fuzzy_group.conf`):

| Символ                                     | Штатно | У нас |
| ------------------------------------------ | ------ | ----- |
| `DBL_SPAM`                                 | 6.5    | 5.0   |
| `DBL_PHISH` / `DBL_MALWARE` / `DBL_BOTNET` | 7.5    | 5.5   |
| `URIBL_BLACK`                              | 7.5    | 5.5   |
| `PH_SURBL_MULTI` / `MW_SURBL_MULTI`        | 7.5    | 5.5   |
| `MSBL_EBL`                                 | 7.5    | 5.5   |
| `RBL_SPAMHAUS_DROP`                        | 7.0    | 5.5   |
| `FUZZY_DENIED`                             | 12.0   | 5.5   |

Проверено (`infra/test-antispam.sh`, п. 6): письмо с доменом из Spamhaus DBL
набирает 4.90 балла и получает действие `no action` — в спам не уходит.
Две независимые сработки (например, DBL + нечёткая база) дают 10.5 — папка
Спам. До отказа (15) нужны три и больше.

Отдельно снижены эвристики по отсутствию обратной DNS-записи
(`RDNS_NONE` 2.0 → 1.0, `HFILTER_HOSTNAME_UNKNOWN` 2.5 → 1.0,
`local.d/hfilter_group.conf`): у небольших легитимных отправителей PTR часто
нет, и вместе с парой мелочей письмо перескакивало порог.

### Тестовый образец GTUBE

Штатно rspamd на строку GTUBE сразу ставит `reject`, минуя подсчёт баллов, —
письмо отбивается на SMTP и в ящик не попадает. Нам нужно, чтобы образец
проходил весь конвейер и укладывался в папку Спам, поэтому встроенная
обработка выключена (`gtube_patterns = "disabled"` в `local.d/options.inc`), а
сама строка ловится правилом `BLACKLIST_CONTENT` (вес 8) из
`maps.d/blacklist_content.map`.

## 5. Своя почта между своими

Письмо от нашего пользователя всегда приходит через `submission:587` с
SASL-аутентификацией (порт 25 аутентификацию не принимает). Значит «свой
отправитель» == прошёл аутентификацию. Для таких писем внешние источники
не спрашиваются **вообще** — `infra/rspamd/local.d/settings.conf`:

- отключены группы символов `rbl`, `spamhaus`, `surbl`, `surblorg`, `uribl`,
  `rspamdbl`, `ebl`, `sem`, `blocklistde`, `mailspike`, `dnswl`, `fuzzy`,
  `phishing`, `hfilter`, `mx`;
- пороги для своих мягче: в Спам — 12, отказ — 25.

Дублирующая защита на уровне модуля: `exclude_users = true` у списков доменов
в `local.d/rbl.conf`.

Проверено (`infra/test-antispam.sh`, п. 4) на одном и том же письме со ссылкой
на домен из Spamhaus DBL:

```
  [OK] то же письмо от аутентифицированного пользователя: символов внешних списков нет
  [OK] к своим применён отдельный профиль порогов (reject = 25)
  [OK] в кэше резольвера нет ни одного обращения к dbl.spamhaus.org — запросы не уходили
```

Последняя строка — самое важное: проверяется не только отсутствие символов, но
и то, что DNS-запрос физически не ушёл (кэш резольвера пуст по этой зоне).
Заодно это приватность: домены из переписки пользователей не утекают в чужие
DNS-серверы.

## 6. Где лежат настройки для админки

Всё, что админка должна уметь менять, лежит в файлах с предсказуемой
структурой, а не размазано по конфигам.

### 6.1 Пороги

`infra/rspamd/local.d/actions.conf` — строки строго вида `имя = значение;`,
по одной на строку, без вложенности. Читается и переписывается регулярным
выражением. Применение изменений без простоя:

```bash
docker compose -f infra/docker-compose.yml kill -s HUP rspamd
```

### 6.2 Белые и чёрные списки

Каталог `infra/rspamd/maps.d/` примонтирован в контейнер **на запись**
(`/etc/rspamd/maps.d`). Формат — обычный текст, одна запись в строке, строки
с `#` игнорируются. Rspamd следит за временем изменения файла и перечитывает
карту сам: `map_watch_interval = 10s` в `local.d/options.inc`. **Перезапуск
не нужен.**

| Файл                        | Содержимое                           | Символ                     | Вес |
| --------------------------- | ------------------------------------ | -------------------------- | --- |
| `whitelist_from.map`        | адреса отправителей                  | `WHITELIST_SENDER_ADDRESS` | −10 |
| `whitelist_domains.map`     | домены отправителей                  | `WHITELIST_SENDER_DOMAIN`  | −6  |
| `whitelist_ip.map`          | IP или CIDR отправляющих серверов    | `WHITELIST_IP`             | −6  |
| `local_domains.map`         | собственные домены сервера           | `LOCAL_SENDER_DOMAIN`      | −2  |
| `blacklist_from.map`        | адреса отправителей                  | `BLACKLIST_SENDER_ADDRESS` | +12 |
| `blacklist_domains.map`     | домены отправителей                  | `BLACKLIST_SENDER_DOMAIN`  | +10 |
| `blacklist_url_domains.map` | домены ссылок внутри письма          | `BLACKLIST_URL_DOMAIN`     | +8  |
| `blacklist_content.map`     | регулярные выражения по всему письму | `BLACKLIST_CONTENT`        | +8  |

Веса заданы в `infra/rspamd/local.d/multimap.conf`. Логика: белый список
перебивает типовое ложное срабатывание (6–10 баллов), чёрный гарантированно
доводит до порога «в Спам», но не до отказа — отказ администратор ставит
осознанно, подняв вес до 15.

Проверено (`infra/test-antispam.sh`, п. 7): добавление домена в
`blacklist_domains.map` помечает письмо спамом через 10 секунд без
перезапуска, добавление адреса в `whitelist_from.map` — снимает пометку.

`local_domains.map` должен совпадать с таблицей `virtual_domains` в Postgres.
Основной домен (`MAIL_DOMAIN`) дописывает entrypoint при старте; остальные
пока синхронизируются вручную — это естественное место для доработки админки.

### 6.3 Статистика и обучение — через HTTP-API rspamd

Веб-интерфейс и API контроллера: `http://127.0.0.1:11334`, пароль
`RSPAMD_PASSWORD` в заголовке `Password`.

| Что нужно админке                                   | Точка API                                   |
| --------------------------------------------------- | ------------------------------------------- |
| Сколько писем проверено, сколько помечено, действия | `GET /stat`                                 |
| Какие правила срабатывают чаще всего                | `GET /graph`, `GET /history`                |
| Список символов, групп и весов                      | `GET /symbols`                              |
| Ручное обучение на примере спама                    | `POST /learnspam` (тело — письмо)           |
| Ручное обучение на примере не-спама                 | `POST /learnham`                            |
| Проверить произвольное письмо                       | `POST /checkv2`                             |
| Состояние источников                                | символы `*_BLOCKED*` в результатах проверок |

Байесовская статистика и данные модуля `replies` хранятся в Redis
(база стека, пароль `REDIS_PASSWORD`).

## 7. Раскладка в папку Спам — сделано

Реализован вариант A. В образ Dovecot добавлены `dovecot-sieve` и
`dovecot-managesieved`, в `protocol lmtp` включён плагин `sieve`, а глобальный
фильтр `infra/dovecot/sieve/spam-to-junk.sieve` уносит письма с заголовком
`X-Spam: Yes` в папку «Спам». Проверка в `infra/test-antispam.sh` подтверждает:
«письмо лежит в папке Спам» — OK.

Sieve выбран не только ради спама: на нём же будут работать пользовательские
правила фильтрации, а условия и действия из эталонного интерфейса
(см. `docs/features-reference.md`) ложатся на Sieve один в один. Путь к личным
правилам уже прописан (`sieve = file:…/sieve;active=…/.dovecot.sieve`).

### Побочное открытие: письма с кириллицей без MIME-кодирования выглядят как спам

После включения раскладки проверки полнотекстового поиска покраснели — но не
из-за антиспама. Тестовый скрипт слал письма с кириллицей в теме без
MIME-кодирования, без charset и с заявленным 7-битным переносом при 8-битном
содержимом. Rspamd справедливо начислял за это `R_BAD_CTE_7BIT` (3.5),
`BROKEN_CONTENT_TYPE` (1.5), `SUBJECT_NEEDS_ENCODING` (1.0) и
`R_MISSING_CHARSET` (0.5) — вместе 6.5 балла при пороге 6, и письмо уезжало
в «Спам», а проверки искали его во «Входящих».

Вывод двойной. Скрипт проверки исправлен — он теперь формирует корректные
письма. А для продукта это напоминание: **исходящая почта обязана быть
правильно закодирована, иначе она попадёт в спам у получателей**. Наш
собственный отправитель проверен: тема уходит как `=?UTF-8?B?…?=`,
тело с явным charset — здесь всё в порядке.

## 7.1. Прежнее описание (оставлено для истории)

Rspamd помечает спам заголовками (проверено):

```
X-Spam: Yes
X-Spam-Status: Yes, score=7.90
X-Spam-Level: *******
X-Spamd-Bar: +++++++
X-Spamd-Result: default: True [7.90 / 15.00]; BLACKLIST_CONTENT(8.00)...
```

Но **разложить письмо по папкам может только принимающая сторона** — Dovecot.
Сейчас в `infra/dovecot/` нет ни Sieve, ни `lmtp_save_to_detail_mailbox`,
поэтому помеченное письмо остаётся в INBOX. Это единственный пункт, который
не закрывается в зоне антиспама. Нужен один из двух вариантов.

**Вариант A (рекомендуемый) — глобальный Sieve-фильтр.** В
`infra/dovecot/Dockerfile` добавить пакет `dovecot-sieve`, в
`dovecot.conf.template`:

```
protocol lmtp {
  mail_plugins = $mail_plugins sieve
}
plugin {
  sieve_before = /etc/dovecot/sieve/spam-to-junk.sieve
}
```

и сам фильтр `spam-to-junk.sieve`:

```
require ["fileinto", "mailbox"];
if header :is "X-Spam" "Yes" {
  fileinto :create "Spam";
  stop;
}
```

Папка `Spam` со `special_use = \Junk` в namespace уже есть.

**Вариант B (без новых пакетов)** — две строки в `dovecot.conf.template`:
`recipient_delimiter = +` и `lmtp_save_to_detail_mailbox = yes` в
`protocol lmtp`, плюс правило rspamd, переписывающее получателя на
`пользователь+Spam@домен`. Проще в установке, но меняет поведение всех
адресов с «плюсом», поэтому вариант A лучше.

После любого из вариантов проверка п. 2 в `infra/test-antispam.sh` начнёт
находить письмо в папке `Spam` и `[ПРОПУСК]` сменится на `[OK]` — менять
скрипт не нужно.

## 8. Расход памяти

Замерено `docker stats --no-stream` на этом стенде.

| Контейнер   |  До (МиБ) | После (МиБ) |
| ----------- | --------: | ----------: |
| rspamd      |     152.0 |       155.9 |
| autoconfig  |      35.1 |        33.8 |
| postgres    |      31.7 |        31.5 |
| postfix     |      15.0 |        28.1 |
| dovecot     |      13.3 |        25.8 |
| nginx       |      26.0 |        25.2 |
| redis       |       6.7 |         6.7 |
| **unbound** |         — |     **4.5** |
| **Итого**   | **279.9** |   **311.2** |

Резольвер стоит 4–8 МиБ — это цена того, чтобы проверки по спискам вообще
работали. Показания rspamd, dovecot и postfix между замерами «плавают» в
пределах десятков мегабайт (кэши, скомпилированные регулярные выражения,
свежесть контейнера): три подряд замера итога дали 291, 302 и 311 МиБ.
Корректно читать как «стек остался в районе 300 МБ», прирост от антиспама —
единицы мегабайт на резольвер плюс несколько мегабайт на дополнительные
правила rspamd.

С включённым ClamAV к этому добавляется **1.03 ГиБ** — отсюда и решение
держать антивирус выключенным по умолчанию.

## 9. Проверка

```bash
bash infra/test-antispam.sh
```

Последний прогон: **OK=38, FAIL=0, ПРОПУЩЕНО=2**.
Пропуски: раскладка в папку Спам (раздел 7) и антивирус (выключен по
умолчанию — при `CLAMAV_ENABLED=true` проверка EICAR выполняется).

Что покрыто:

1. Резольвер работает; контрольные точки Spamhaus ZEN, DBL, URIBL, SURBL
   отвечают через него и блокируются через публичный — с реальным выводом.
2. rspamd и postfix ходят в DNS именно через unbound.
3. Rspamd действительно получает вердикт списка (символ `DBL_SPAM`), а не
   молча пропускает.
4. GTUBE принимается, помечается `X-Spam: Yes`, действие «в Спам».
5. Обычное деловое письмо не помечается (ложных срабатываний нет).
6. Письмо своего пользователя своему не проверяется внешними списками —
   с проверкой по кэшу резольвера, что запросы не уходили.
7. При остановленном резольвере почта продолжает ходить (доставка за ~7 с).
8. Ни один внешний список в одиночку не дотягивает до порога.
9. Белые и чёрные списки админки применяются на лету, белый перебивает чёрный.
10. Замер памяти.

Смежные регрессионные тесты должны оставаться зелёными:

```bash
bash infra/test-delivery.sh    # 14/14
bash infra/test-fts-quota.sh   # 39/39
```
