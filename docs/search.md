# Полнотекстовый поиск и квоты в Dovecot

Два связанных механизма, оба живут в `infra/dovecot/`.

- Поиск — плагин **FTS Xapian** (`dovecot-fts-xapian`), встраивается прямо
  в `IMAP SEARCH`. Java не тянет, индекс держит на диске, в памяти —
  единицы мегабайт.
- Квоты — штатный плагин **quota** с бэкендом `maildir`, лимит берётся из
  `virtual_users.quota_bytes` в Postgres.

## Быстрая проверка

```bash
bash infra/test-fts-quota.sh          # 39 проверок: поиск, вложения, квоты
bash infra/test-delivery.sh           # сквозная доставка (не должна сломаться)
```

## Полнотекстовый поиск

### Почему Xapian, а не Solr

`docs/features-mailru.md` требует, чтобы поиск находил слово **внутри PDF** и
показывал фрагмент документа. Штатный IMAP SEARCH так не умеет: он перебирает
письма и про содержимое вложений ничего не знает. Из полнотекстовых движков для
Dovecot Solr тянет за собой JVM и сотни мегабайт памяти — это противоречит
требованию «быстрый и небольшой». Xapian — библиотека, работает внутри процессов
Dovecot, добавляет к контейнеру единицы мегабайт.

### Что индексируется

- Тема, тело, адреса (`From`, `To`, `Cc`, …) — штатно.
- **Содержимое вложений** — через механизм `fts_decoder`. Dovecot передаёт
  не-текстовую часть письма службе `decode2text`, а та — скрипту
  `infra/dovecot/decode2text.sh`, который зовёт внешний разборщик и возвращает
  UTF-8 текст.

| Формат | Разборщик | Пакет |
|--------|-----------|-------|
| PDF | `pdftotext` | poppler-utils |
| .doc / .ppt / .xls | `catdoc`, `catppt`, `xls2csv` | catdoc |
| .docx / .xlsx / .pptx | `unzip` + штатный `/usr/lib/dovecot/xml2text` | unzip |
| .odt / .ods / .odp | то же | unzip |
| .rtf | `unrtf` | unrtf |

Текстовые вложения (`text/plain`, `text/html`) Dovecot разбирает сам, скрипт для
них не нужен. Вложения крупнее 50 МБ не разбираются (`fts_message_max_size`).

Скрипт вызывается двумя способами: без аргументов — печатает список
поддерживаемых типов (Dovecot спрашивает один раз, чтобы не гонять зря
неподдерживаемые вложения), с Content-Type в первом аргументе — читает вложение
со stdin и печатает текст. Второй столбец списка — расширение файла: по нему тип
угадывается, если клиент прислал вложение как `application/octet-stream`.

### Когда строится индекс

`fts_autoindex = yes`: при доставке письма LMTP ставит задачу службе `indexer`,
а `indexer-worker` строит индекс **в фоне**. К моменту первого поиска индекс уже
готов. `fts_enforced = yes` — поиск всегда идёт через индекс, а не сваливается
в медленный перебор.

Спам и Корзина в фоне не индексируются (`fts_autoindex_exclude`) — как в
mail.ru, где поиск по умолчанию туда не заглядывает и предлагает отдельную
кнопку «Искать в спаме и корзине».

### Где лежит индекс

Отдельный постоянный том `mailindex` смонтирован в `/var/mail/index`:

```
/var/mail/index/<домен>/<логин>/xapian-indexes/db_<id папки>
```

Индексы вынесены из Maildir специально: они не попадают в подсчёт квоты и не
мешают резервному копированию писем. Том переживает и перезапуск, и пересоздание
контейнера — поиск работает сразу, без переиндексации (проверяется в тесте, п. 7).

### Переиндексация

```bash
bash infra/scripts/fts-reindex.sh                      # все активные ящики
bash infra/scripts/fts-reindex.sh user@mail.local      # один ящик
bash infra/scripts/fts-reindex.sh --purge user@mail.local  # снести и собрать заново
```

Без `--purge` индекс достраивается. `--purge` удаляет каталог `xapian-indexes`
целиком — нужно после смены параметров индексации (`partial`/`full`) или если
индекс повреждён. Перебор всех ящиков (`doveadm -A`) работает благодаря
`iterate_query` в `dovecot-sql.conf.ext`.

### Русский язык: что работает, а что нет

Проверено на живом стеке:

- **Регистр не важен**: `ДОКУМЕНТАМИ` находит `документами`.
- **Буква ё приравнена к е** в обе стороны: `елка` находит `Ёлка`,
  `приемной` находит `приёмной`. Xapian нормализует диакритику при индексации.
- **Словоформы — по префиксу**: `fts_xapian = partial=3 full=20` индексирует
  n-граммы от 3 до 20 символов от начала слова, поэтому запрос `документ`
  находит `документы`, `документами`, `документов`.

**Ограничение, о котором надо знать.** Это префиксное совпадение, а не
морфология: обратное направление не работает — запрос `документами` **не**
найдёт письмо со словом `документ`. Настоящей лемматизации в `fts-xapian` 1.5.5
(версия в Debian bookworm) нет. Практический вывод для веб-интерфейса: перед
отправкой запроса в IMAP имеет смысл обрезать у русских слов хвост окончания
(или искать по нескольким вариантам), иначе часть писем не найдётся.

### Язык поисковых запросов

Строка поиска понимает условия: `от:волкова есть:вложение новее:1мес`.
Грамматика лежит в **одном** месте на весь продукт —
`packages/shared/src/search.ts`, — и это не вопрос вкуса. Разбор нужен обеим
сторонам: серверу — чтобы превратить условия в `IMAP SEARCH`, браузеру —
чтобы нарисовать чипы «Запрос понят так», не обрезать окончание у названия
оператора и применить `папка:`. Две реализации одной грамматики разошлись бы
молча: браузер рисовал бы чип «Тема: договор», а сервер искал бы слова
«тема:договор» в теле письма.

| Оператор | Синоним | Что делает | Кто применяет |
| --- | --- | --- | --- |
| `от:` | `from:` | отправитель | сервер, `FROM` |
| `кому:` | `to:` | получатель | сервер, `TO` |
| `копия:` | `cc:` | адрес в копии | сервер, `CC` |
| `тема:` | `subject:` | слово в теме | сервер, `SUBJECT` |
| `есть:вложение` | `has:attachment` | только письма с вложениями | сервер, разбор BODYSTRUCTURE |
| `файл:` | `filename:` | имя или расширение вложения | сервер, разбор BODYSTRUCTURE |
| `папка:` | `folder:` | где искать | **браузер** (см. ниже) |
| `после:` / `до:` | `after:` / `before:` | границы по дате (ГГГГ-ММ-ДД) | сервер, `SINCE`/`BEFORE` |
| `новее:` / `старше:` | `newer_than:` / `older_than:` | срок: `7д`, `2нед`, `3мес`, `1г` | сервер, `SINCE`/`BEFORE` |
| `больше:` / `меньше:` | `larger:` / `smaller:` | размер письма: `5м`, `100к` | сервер, `LARGER`/`SMALLER` |
| `непрочитанные`, `прочитанные`, `важные` | `unread`, `read`, `flagged` | слова-признаки, двоеточие не нужно | сервер, флаги |

**Почему `папка:` применяет браузер.** У IMAP папка — не условие поиска,
а то, что открыто ДО поиска. В запросе к API папка уже названа параметром
`folderId`, так что применить оператор серверу нечем. Разбирает он его всё
равно — ради одного: чтобы `папка:Рассылки` не ушло в полнотекстовый поиск
обычными словами и не отдало пустоту. Браузер же именно папками и выбирает,
кого опрашивать (`useSearch`), поэтому оператор там работает по-настоящему.
Названа несуществующая папка — интерфейс говорит об этом прямо, а не молчит
пустой выдачей.

**Имени файла в индексе нет.** `filename:` у Gmail — поле их собственного
индекса; у IMAP такого условия поиска не существует вовсе. Имя сверяется
по BODYSTRUCTURE, той же самой, по которой уже отбирается «с вложениями»
и рисуется скрепка в списке, — лишней команды к серверу это не стоит.

**Устойчивость важнее строгости.** Оператором считается только известное
слово из списка с осмысленным значением; всё прочее — обычные слова
полнотекстового поиска. Двоеточие в русском тексте встречается сплошь и
рядом («Договор № 452/26: правки», «встреча 14:30», «Re: смета»), и
разборщик, объявляющий такое ошибкой или полем, ломал бы ровно те запросы,
которые человек набрал правильно. Незакрытая кавычка — не отказ, а
недопечатанная строка: `тема:"годовой отчёт` читается как
`тема:годовой отчёт`. Ёлочки (`«»`) понимаются наравне с прямыми кавычками:
фразу в поиск чаще вставляют из редактора, чем набирают.

**Обрезка окончаний знает про операторы.** Поиск префиксный (см. выше),
поэтому браузер перед отправкой обрезает у русских слов хвост окончания
(`apps/web/src/lib/searchQuery.ts`). Обрезка, не знающая грамматики, ломала
операторы: слово-признак `непрочитанные` превращалось в `непрочитанн`,
сервер такого признака не узнавал, и запрос молча становился полнотекстовым
поиском слова, которого нет ни в одном письме. Теперь обрезаются только
свободные слова и значение `тема:`; названия операторов, адреса, имена
файлов, даты и размеры не трогаются.

### Сохранённые запросы

Часто повторяемый поиск сохраняется под именем: `GET/POST/DELETE
/api/searches`, таблица `mail_saved_searches` (миграция 0027). В базе лежит
**строка запроса**, а не разобранные поля: язык растёт, и разложенный по
колонкам запрос требовал бы миграции на каждый новый оператор, а старые
сохранённые запросы после такой миграции значили бы уже не то, что человек
сохранял.

Возможность целиком зависит от базы. Нет базы или не применена миграция —
`available: false` с причиной, и интерфейс не показывает ни кнопки
«Сохранить запрос», ни группы в левой колонке. То же правило, что у меток и
отложенных писем: кнопка появляется вместе с поведением.

**Сохранённый запрос не притворяется папкой.** В Thunderbird сохранённый
поиск выглядит папкой, и это сбивает: в такую «папку» нельзя переложить
письмо, её нельзя очистить, а письмо из неё лежит совсем не там, где
показано. Здесь у него свой заголовок группы, значок лупы вместо папки,
строка запроса под именем и ни одного обработчика переноса — перетащить на
него письмо нечем.

### Фрагменты и подсветка

Для карточки вложения с подсвеченным фрагментом (как в mail.ru) сервер уже
объявляет `SNIPPET=FUZZY` и `PREVIEW=FUZZY` в CAPABILITY — фрагмент можно взять
IMAP-командой `SNIPPET`, а не вытаскивать письмо целиком.

Агрегаты для фасетных фильтров (сколько совпадений в каждой папке, по месяцам и
годам) считаются на стороне API: тот же поисковый запрос выполняется по нужным
папкам и результаты группируются по дате. Отдельного «фасетного» API у Dovecot
нет.

### Скорость

Замер на ящике из 120 писем: `IMAP SEARCH TEXT "наполнитель"` — **0.009 сек**
(120 совпадений), поиск по слову внутри PDF — **0.010 сек**. Время берётся из
ответа самого Dovecot: `c OK Search completed (0.009 + 0.000 + 0.008 secs)`.

## Квоты

### Откуда берётся лимит

`userdb` переведён с `static` на `sql`, и `user_query` отдаёт Dovecot
`quota_rule`:

```sql
SELECT '/var/mail/vhosts/%d/%n' AS home, 5000 AS uid, 5000 AS gid,
       '*:bytes=' || quota_bytes AS quota_rule
FROM virtual_users WHERE email = '%u' AND active
```

`quota_bytes = 0` означает «без ограничения» (Dovecot так трактует `bytes=0`).
Менять квоту можно прямо в Postgres — новое значение подхватится со следующей
сессии, перезапуск не нужен.

Бэкенд — `maildir`: занятое место считается по файлу `maildirsize` внутри
Maildir. Никаких внешних словарей и лишней памяти.

### Что видит клиент

Плагин `imap_quota` включает расширение QUOTA:

```
* QUOTAROOT INBOX "User quota"
* QUOTA "User quota" (STORAGE 48 1048576)
```

Числа в килобайтах. Веб-API отдаёт их в `GET /api/account`
(`quotaUsedBytes` / `quotaLimitBytes`).

### Предупреждение и отказ

- **90% и 95%** — служба `quota-warning` кладёт в ящик письмо
  «Ящик заполнен на N%» (скрипт `infra/dovecot/quota-warning.sh`, доставка через
  `dovecot-lda` с `noenforcing`, иначе предупреждение само не влезет).
- **Превышение при доставке** — LMTP отвечает
  `552 5.2.2 Mailbox is over quota / Ящик получателя переполнен`.
  Postfix возвращает письмо отправителю (`dsn=5.2.2, status=bounced`).
  Молча письмо не теряется.
- **Отказ ещё на приёме** — служба `quota-status` (порт 12340) работает как
  policy-сервис Postfix. В `infra/postfix/conf/main.cf.template`:

  ```
  smtpd_recipient_restrictions =
      permit_mynetworks,
      permit_sasl_authenticated,
      reject_unauth_destination,
      check_policy_service inet:dovecot:12340
  ```

  Отправитель получает `552 5.2.2 ... Recipient address rejected: Mailbox is
  over quota` прямо на `RCPT TO`, не передавая тело письма.

`lmtp_rcpt_check_quota = yes` заставляет и сам LMTP проверять квоту на этапе
RCPT — это подстраховка на случай, если письмо пришло мимо policy-сервиса.

### Тонкость про службы Dovecot и журнал

`log_path = /dev/stdout` — это `/proc/self/fd/1`. У процессов службы `script`
(`quota-warning`, `decode2text`) на fd 1 висит сокет вызывающего процесса, и
открыть его как файл нельзя — `dovecot-lda` падал с
`Can't open log file /dev/stdout`. Поэтому `quota-warning.sh` первым делом делает
`exec 1>&2` (на stderr — настоящий журнал контейнера), а служба запускается от
root, как и штатный LDA, который сам сбрасывает права до `vmail`.

## Что добавилось в образ и сколько это стоит

Пакеты: `dovecot-fts-xapian`, `poppler-utils`, `catdoc`, `unzip`, `unrtf`.

- Образ `mailtrue-dovecot`: **247 МБ** (был ~180 МБ) — в основном poppler
  и его зависимости. Это диск, не память.
- Память контейнера dovecot: **10.3 МБ → 15.4 МБ** (+5 МБ). Индексация в фоне
  поднимает `indexer-worker` (`vsz_limit = 2G`, `process_limit = 2`) — это
  виртуальное адресное пространство, реально расходуется существенно меньше.
