# Перенос из Kerio Connect: по шагам

Предыдущая глава описывает средство переноса вообще. Эта — конкретный путь
для Kerio Connect, от выгрузки списка сотрудников до переключения почты.
Порядок шагов выбран так, чтобы **в любой момент можно было остановиться и
вернуться к старому серверу**: до последнего шага он продолжает работать.

## Шаг 0. Что переносится, а что нет

Переносится **почта**: письма со всеми заголовками и вложениями, флажки
(прочитано, отвечено, помечено), структура папок вместе с вложенными, даты
получения.

**Не переносится**: календари, контакты и задачи Kerio. Они недоступны по
IMAP в принципе, и никакое средство переноса по IMAP их не заберёт. Если они
нужны — выгружайте их из Kerio отдельно, до отключения сервера.

## Шаг 1. Список сотрудников из Kerio

В консоли администратора Kerio Connect: **Accounts → Users → выбрать домен →
Export**. Получится файл вида `users_example.com_2026-08-05.csv`.

Превратите его в список ящиков для создания:

```bash
node packages/migrate/dist/cli.js kerio-users \
  --file users_example.com_2026-08-05.csv \
  --domain ваш-домен.ru \
  --out users.json
```

Если `--domain` не указать, домен возьмётся из имени файла выгрузки.
Второй и последующие адреса сотрудника станут алиасами.

> **Про пароли.** Kerio выгружает пароли **открытым текстом** — это его
> особенность, не наша. Поэтому по умолчанию средство переноса пароли в свой
> вывод не кладёт. Флаг `--with-passwords` их добавит, но пользоваться им
> стоит только для немедленного создания ящиков, а файл сразу после этого
> удалить. Файл с паролями создаётся с правами `600`, чтобы его не прочитал
> любой пользователь системы.
>
> Разумнее пароли не переносить вовсе, а задать новые и раздать сотрудникам.
> Это заодно закрывает вопрос со старыми слабыми паролями.

Если выгрузка окажется битой (незакрытая кавычка — обычное дело при ручной
правке), разбор остановится с указанием номера строки. Это сделано намеренно:
молчаливый разбор такого файла раньше приводил к тому, что ящики для части
сотрудников просто не создавались, и это замечали по отбивающейся почте.

## Шаг 2. Ящики на новом сервере

Заведите ящики — либо импортом CSV в панели администратора, либо скриптом:

```bash
bash infra/scripts/create-mailbox.sh ivanov@ваш-домен.ru 'новый-пароль'
```

Пока ничего не сломано: MX-запись домена по-прежнему указывает на Kerio, вся
почта идёт туда.

## Шаг 3. Пробный перенос одного ящика

Не начинайте со всех. Возьмите один ящик — желательно свой:

```bash
# Пароли — через файл, а не аргументом командной строки: аргумент виден
# в системе каждому (ps aux), а перенос большого ящика идёт часами.
printf '%s' 'пароль-в-kerio' > /root/kerio.pass && chmod 600 /root/kerio.pass
export MIGRATE_DEST_PASS='пароль-у-нас'

node packages/migrate/dist/cli.js run \
  --source-host kerio.example.com --source-port 993 --source-secure \
  --source-user ivanov --source-pass-file /root/kerio.pass \
  --dest-host 127.0.0.1 --dest-port 143 \
  --dest-user ivanov@ваш-домен.ru \
  --state ./migrate-state/ivanov.jsonl \
  --report ivanov-report.json
```

Проверка сертификатов по умолчанию отключена — у Kerio они часто
самоподписанные. Если сертификат настоящий, добавьте `--strict-tls`.

Полезно перед настоящим переносом посмотреть план: `--dry-run` покажет, какие
папки во что превратятся и сколько там писем, ничего не копируя.

Войдите в новый ящик через веб-интерфейс и проверьте своими глазами: те ли
папки, на месте ли вложения, сохранились ли даты, отмечены ли прочитанными те
письма, что были прочитаны. На этом шаге ошибка стоит десять минут, а после
переноса всех ящиков — рабочий день.

Если имена папок в Kerio не совпадают с нашими, задайте соответствие:
`--map 'Public Folders/Общая=Общие/Архив'`. Ненужные папки пропускаются:
`--exclude 'Календарь'`. Оба флага можно повторять.

## Шаг 4. Перенос всех ящиков

Список ящиков — в CSV с обязательной строкой заголовка:

```csv
source_host,source_port,source_secure,source_user,source_pass,dest_user,dest_pass
kerio.example.com,993,true,ivanov,pass1,ivanov@ваш-домен.ru,newpass1
kerio.example.com,993,true,petrov,pass2,petrov@ваш-домен.ru,newpass2
```

```bash
node packages/migrate/dist/cli.js batch \
  --file accounts.csv --concurrency 2 \
  --dest-host 127.0.0.1 --dest-port 143 \
  --state-dir ./migrate-state --report batch-report.json
```

Перенос можно прерывать и запускать снова: он помнит, где остановился, и
**не создаёт дублей** — уже перенесённые письма опознаются и пропускаются.
Это важнее, чем кажется: перенос большого ящика идёт часами, и возможность
прервать его, не начиная заново, определяет, влезет ли переезд в выходные.

Прогоните перенос заранее, за несколько дней до переключения. Почта в это
время продолжает приходить на Kerio.

## Шаг 5. Докачка и переключение

Накануне переключения запустите перенос ещё раз — он заберёт только то, что
пришло с прошлого раза.

Теперь переключайте почту:

1. Уменьшите время жизни (TTL) записей DNS домена до 300 секунд — **за сутки**
   до переключения, чтобы новое значение успело разойтись.
2. Смените MX-запись на новый сервер.
3. Дождитесь, пока почта пойдёт на Mail.True (проверяется письмом со стороннего
   адреса).
4. **Не выключайте Kerio сразу.** Часть отправителей будет ещё сутки-двое
   слать почту по старому адресу.
5. Через два-три дня запустите перенос последний раз — он заберёт то, что
   успело упасть в Kerio после переключения.

## Шаг 6. Почтовые программы сотрудников

Отдельно настраивать ничего не нужно: Mail.True отдаёт настройки по адресу
ящика. В Thunderbird, Outlook или почте телефона сотрудник вводит свой адрес
и пароль — остальное подставится само. Подробности — в главе про почтовые
клиенты.

Предупредите сотрудников об одном: если в почтовой программе стоял старый
сервер, её нужно завести заново, а не править существующую учётную запись.
Иначе программа попытается склеить два разных хранилища.

## Если что-то пошло не так

**Перенос обрывается на одном ящике.** Средство переноса запоминает
неудавшиеся письма отдельно и продолжает с остальными; в конце показывает
список. Чаще всего дело в письме, которое Kerio отдаёт с битым заголовком, —
такое письмо можно перенести вручную.

**Папка не создалась с исходным именем.** Некоторые имена папок Kerio
приёмник не принимает; в этом случае папка создаётся с исправленным именем, и
об этом сообщается в отчёте — письма при этом не теряются.

**Одно письмо оказалось в двух папках Kerio.** Если обе папки отображаются в
одну у нас, копий будет столько же, сколько было в источнике. Это осознанное
поведение: средство переноса считает копии, а не факт наличия письма.
