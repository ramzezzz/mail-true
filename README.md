# Mail.True

Почтовый сервер со своим веб-интерфейсом. Ставится на собственное железо,
работает на своём домене, никому не отдаёт содержимое переписки.

Интерфейс намеренно повторяет mail.ru — люди к нему привыкли, и переучивать
их не нужно. Всё остальное своё: сервер, данные, правила.

Две последние — на языке Node, а не оболочки: они говорят с API так же, как
браузер, и повторяют его запросы буквально. Проверять API запросами из
оболочки оказалось ненадёжно — она портит кодировку тела.

## Устройство

```
              ┌─────────── браузер ───────────┐
              │  apps/web    — почта          │
              │  apps/admin  — админка        │
              └───────────────┬───────────────┘
                              │ REST + WebSocket
              ┌───────────────┴───────────────┐
              │   apps/api — Fastify + TS     │
              └──┬──────────┬─────────┬───────┘
           IMAP  │          │ SQL     │ submission
                 │          │         │
        ┌────────┴───┐ ┌────┴─────┐ ┌─┴────────┐
        │  Dovecot   │ │ Postgres │ │ Postfix  │
        │  Maildir   │ │  Redis   │ │  Rspamd  │
        └────────────┘ └──────────┘ └──────────┘
```

Приёмом и отправкой почты занимаются Postfix и Dovecot, а не собственный код.
Причина простая: доставляемость. Эти программы десятилетиями отлаживались
против особенностей чужих серверов, и письма от них не улетают в спам.
Свой код — там, где он даёт ценность: интерфейс, поиск, управление, перенос.

Письма живут в Maildir и читаются через IMAP. Postgres хранит учётные записи,
домены, настройки и метаданные — но не сами письма, чтобы не было двух
источников истины, которые рано или поздно разойдутся.

## Разработка

Нужны Node 20 или новее и Docker.

```bash
npm install                 # зависимости монорепозитория
npm run stack:up            # поднять почтовый стек
bash infra/test-delivery.sh # проверить, что почта ходит
npm run dev                 # запустить сервер приложения и интерфейс
```

Тестовый ящик разработки: `test@mail.local` / `test12345`.
Создать ещё один:

```bash
bash infra/scripts/create-mailbox.sh user@mail.local 'пароль'
```

Порты стека — все на `127.0.0.1`:

| Порт | Что |
| --- | --- |
| 25 | приём почты по SMTP |
| 587 | отправка (submission, STARTTLS + аутентификация) |
| 143 / 993 | IMAP и IMAPS |
| 110 / 995 | POP3 и POP3S |
| 8025 | сервис автонастройки клиентов |
| 3000 | сервер приложения напрямую (отладка; в бою не публикуется) |
| 8080 / 8443 | nginx: почта, админка, автонастройка (в бою — 80 и 443) |
| 5432 | Postgres |
| 6380 | Redis (не 6379 — тот занят на машине разработки) |
| 11334 | веб-интерфейс Rspamd |

## Помощник на основе ИИ

Выключен по умолчанию и остаётся выключенным, пока администратор домена
не включит его явно. Пока он выключен, интерфейс не показывает ни одной
кнопки ИИ — не показывает и получает отказ, а именно не показывает.

Чтобы включить, нужны две вещи. Первая — миграция:

```bash
docker compose -f infra/docker-compose.yml exec -T postgres \
  psql -v ON_ERROR_STOP=1 -U mailserver -d mailserver \
  < infra/postgres/migrations/0004_ai.sql
```

Вторая — переменная окружения `AI_ENCRYPTION_KEY` в `apps/api/.env`
(минимум 32 символа). Ею шифруется ключ доступа к сервису ИИ: в базе
лежит только шифротекст, поэтому дамп базы без этой переменной
бесполезен. Локальной модели ключ доступа не нужен, и без переменной
она работает — не получится только сохранить ключ внешнего сервиса.

Остальное — адрес сервиса, модель, предел расходов, какие возможности
разрешены — задаётся администратором в разделе «Помощник ИИ» и хранится
в базе. Адрес может указывать на локальную модель, поднятую рядом;
тогда переписка не покидает периметр, и пользователю это видно.

```bash
# локальная модель рядом: совместимый адрес http://127.0.0.1:11434/v1,
# название модели — любое из этого списка
curl http://127.0.0.1:11434/api/tags
```

Моделям с «размышлением» нужен запас по длине ответа: рассуждение тратит
тот же предел, что и полезный текст. Если помощник отвечает «ответ модели
оборван», увеличьте предел длины ответа в настройках домена.

Подробности и требования к приватности — `docs/ai-spec.md`.

## Подключение сторонних почтовых клиентов

Ящик открывается в Thunderbird, Outlook, Apple Mail и мобильных клиентах,
причём достаточно ввести адрес и пароль — настройки клиент находит сам.
Работают все три механизма автоопределения сразу: Mozilla Autoconfig,
Microsoft Autodiscover и записи SRV, плюс отдельный профиль для Apple.

Список DNS-записей, которые нужно опубликовать при боевой установке,
выдаёт сам сервис:

```bash
curl "http://127.0.0.1:8025/api/dns-records?domain=example.ru"   # что публиковать
curl "http://127.0.0.1:8025/api/dns-check?domain=example.ru"     # что уже опубликовано
```

Ключ DKIM подставляется настоящий — тот, что сгенерировал Rspamd.
